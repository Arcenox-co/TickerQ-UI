# v10.2.0

**Release Date:** March 2026
**.NET Target:** .NET 10
**Equivalent Versions:** [v9.2.0](./v9.2.0) | [v8.2.0](./v8.2.0)

## New Features

### Per-Function Concurrency Control
Control how many instances of a specific ticker function can run simultaneously using the new `maxConcurrency` parameter on `[TickerFunction]`.

```csharp
// Only one instance of this function runs at a time — excess work is queued, not skipped
[TickerFunction("ProcessPayment", maxConcurrency: 1)]
public async Task ProcessPayment(TickerFunctionContext context)
{
    // ...
}

// Allow up to 3 concurrent executions
[TickerFunction("SendNotification", maxConcurrency: 3)]
public async Task SendNotification(TickerFunctionContext context)
{
    // ...
}
```

Unlike `SkipIfAlreadyRunning()` (which discards excess executions), `maxConcurrency` **queues** them — when one completes, the next proceeds. Works for both TimeTickers and CronTickers.

- Default value `0` means unlimited (backward compatible)
- New compile-time diagnostic `TQ011` if a negative value is used
- See [Attributes API Reference](/api-reference/attributes) for details

### CronTicker Enable/Disable Support
CronTickers now have a full-stack `IsEnabled` property. Disabled cron tickers stop generating new occurrences and can be toggled from the dashboard or programmatically via the manager API.

```csharp
var cronTicker = new CronTickerEntity
{
    Function = "NightlyReport",
    Expression = "0 0 2 * * *",
    IsEnabled = false // Start disabled
};
```

### Dashboard Timezone-Aware Date Formatting
The dashboard now formats dates based on the selected timezone region:
- **European timezones** → `dd/MM/yyyy`
- **American timezones** → `MM/dd/yyyy`
- **Other timezones** → `yyyy-MM-dd` (ISO)

This applies to all tables, detail views, graphs, and date pickers.

## Bug Fixes

- **Redis persistence not filtering disabled cron tickers** — `GetAllCronTickerExpressions` now correctly skips disabled cron tickers, consistent with EF Core and InMemory providers
- **Dashboard cron ticker toggle dialog showing inverted text** — Clicking "Disable" no longer shows "Enable" confirmation and vice versa
- **Dashboard BasePath not working with `UsePathBase`** — Fixed path resolution when the application uses ASP.NET Core's `UsePathBase` middleware
- **CSP compliance** — Eliminated inline scripts from the dashboard for `script-src 'self'` Content Security Policy support
- **Empty request deserialization** — Fixed `JsonException` when deserializing ticker functions with no request payload
- **Source generator namespace sanitization** — Fixed handling of assemblies with invalid C# identifier characters in their names
- **Design-time DbContext failure** — Fixed crash when `TickerQEfCoreOptionBuilder` is unavailable during EF Core design-time operations (e.g., `dotnet ef migrations add`)
- **Redis overriding EF Core provider** — Fixed `AddStackExchangeRedis` incorrectly replacing the EF Core persistence provider registration
- **Dashboard with old `Startup.cs` pattern** — Fixed failure when the host doesn't implement `IApplicationBuilder` directly
- **`TickerModelCustomizer` schema** — Fixed configured schema not being applied correctly
- **EF Core MySQL type mapping** — Fixed type mapping error for MySQL providers in `MigrateDefinedCronTickers`
- **Dashboard JSON serialization** — Replaced reflection-based serialization with source-generated serializers for better performance and trimming support

## Improvements

- **Relaxed abstractions version constraints** — More flexible version compatibility between TickerQ packages
- **Centralized test project versions** — Improved cross-branch test compatibility
- **Dashboard OpenAPI group name** — Added `SetGroupName()` to organize dashboard endpoints in API documentation
- **`UseApplicationDbContext` fix** — Corrected implementation for sharing the application's DbContext

## Migration Required

::: warning EF Core Users — New Migration Needed
This release adds the `IsEnabled` column to the `CronTicker` table. If you are using Entity Framework Core as your persistence provider, you **must** add a new migration after upgrading:

```bash
dotnet ef migrations add AddCronTickerIsEnabled
dotnet ef database update
```

The new column defaults to `true`, so all existing cron tickers will remain enabled after the migration — no data loss or behavior change.
:::
